  - 备注
  - 工资结算备注
- 导入确认弹窗增加“未生成实际课时”数量。

### v8.8.4
- 调整课时管理初始月份：
  - 进入课时管理时，如果月份为空，自动填入当前月份。
- 保持课时管理初始列表显示全部学生数据。
  - 导入类操作仍然必须先选择学生，避免误导入。
- “导入完整课时”改为弹窗式导入：
  - 可拖入 Excel 文件
  - 也可点击按钮选择文件
- 修复完整课时导入确认后报错：
  - null value in column "id" of relation "school_lesson_records" violates not-null constraint
- 原因：
  - 完整课时导入时只给预定课时生成了 id
  - 实际课时没有显式 id，而当前表 id 没有数据库默认值
- 本版改为预定课时和实际课时都显式生成 UUID。
- 本版无 SQL 修改。

### v8.8.1
- 修复支出重新报销后，支出记录状态仍不显示“已报销”的问题。
- 原因：
  - 报销流程不一定把 reimbursement_id / reimbursed_at 写回支出记录本身。
  - 关联关系可能保存在报销记录或报销明细中。
- 本版改为多路径判断支出是否已报销：
  - 支出自身字段
  - 报销记录中的 expense_ids / expenses
  - 报销明细记录中的 expense_id
- 支出列表渲染后会自动补显示“已报销”标识。
- 增加调试函数 `debugReimbursedExpenseIdsV881()`，可在 Console 查看系统识别到的已报销支出 ID。
- 本版无 SQL 修改。

### v8.8
- 新增“导入完整课时”功能。
- 用于导入过去已经完成月份的课时记录。

- 导入批次继续支持“撤回本次导入”。
- 支出记录中，如果支出已经报销，状态区域追加显示“已报销”。
- 主界面版本号完整显示为 v8.8。
- 本版无 SQL 修改。

### v8.7.5
- 再次修复结算锁定 RLS 报错。
- 原因：
  - v8.7.4 只给 authenticated 用户配置了结算锁定表权限。
  - 当前前端直连 Supabase 的运行角色可能是 anon。
  - 所以即使执行了 v8.7.4 SQL，insert 仍然会被 RLS 拦截。
- 新增 `school_v8_7_5_rls_anon_fix.sql`：
  - 允许 anon / authenticated 读取结算锁定记录
  - 允许 anon / authenticated 新增结算锁定记录
  - 允许 anon / authenticated 更新结算锁定记录
  - 允许 anon / authenticated 删除测试结算锁定记录
  - 同时补充 GRANT 权限
- 本版只修 RLS 权限，不改业务逻辑。
- 主界面版本号完整显示为 v8.7.5。
