# 青空进学塾运营管理系统

## 更新记录（倒序）
















































































### v8.5.5
- 修复从左侧某一行预定课时生成实际课时后，实际课时显示到另一行右侧的问题。
- 原因：之前为了兼容旧数据，会在 planned_lesson_id 为空时按日期/科目/老师自动匹配预定课时；当同一周有两条相似预定课时时，可能匹配到错误行。
- 本版显示逻辑改为优先并严格使用实际课时的 planned_lesson_id。
- 从哪一行点击“生成实际”，保存后就固定显示在该行右侧。
- 未带 planned_lesson_id 的旧实际课时不再强行猜测匹配，显示在未关联区域，避免错配。
- 月度结算课时明细同步使用同样的稳定关联逻辑。
- 主界面版本号完整显示为 v8.5.5。
- 本版无 SQL 修改。

### v8.5.4
- 重新排查并修复课时管理右侧实际课时排序问题。
- 原因：右侧实际课时绑定在左侧预定课时行上，单独排序实际课时数组并不会改变整行顺序。
- 本版改为按“预定-实际配对行”整体排序。
- 如果右侧有实际课时，则该行按实际课时日期/时间正序排序。
- 如果右侧没有实际课时，则该行按预定课时日期/时间正序排序。
- 月度结算课时明细同步使用相同配对排序逻辑。
- 主界面版本号完整显示为 v8.5.4。
- 本版无 SQL 修改。

### v8.5.3
- 修复课时管理右侧实际课时按日期倒序显示的问题。
- 右侧实际课时现在按日期正序、开始时间正序排列。
- 月度结算课时明细右侧实际课时也同步改为正序。
- 左侧预定课时仍保留现有课程顺序排序。
- 主界面版本号完整显示为 v8.5.3。

- 月度结算课时明细中，预定课时日期也显示为“日期 + 周”。
- 实际课时日期保持原日期显示，不追加“周”。
- 主界面版本号完整显示为 v8.5.2。

### v8.5.1
- 修复从预定课时生成实际课时时 Supabase 400 报错的问题。
- 原因：v8.5 的收入结算字段误插入到了课时表单，导致保存课时时向课时表提交了不存在的字段。
- 课时保存增加字段白名单，只提交课时表允许的字段。
- 从预定生成实际课时时继续复制：
  - 开始时间
  - 结束时间
  - 时长
  - 课程单价
  - 应收课时费
- 从预定生成实际课时时，上课内容保持空白。
- 主界面版本号完整显示为 v8.5.1。
- 本版无 SQL 修改。
