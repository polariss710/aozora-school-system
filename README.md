### v8.8.13.1

### v8.8.13
- 修复课时管理顶部“预定课时费合计”仍然排除取消课的问题。
- 新口径：
  - 预定课时费合计 = 所有预定课时的“课程单价 × 预定时长”
  - 包含取消课
- 实际课时合计 / 实际课时费合计维持 v8.8.12 口径：
  - 实际课时按实际记录计算
  - 待补课且计费的预定课时计入
  - 取消课不计入
  - 不计费补课不计入
- 修复同一日期/同一周课程出现回数倒序的问题。
- 排序规则加入 `lesson_count`：
  - 同日期、同老师、同科目下，按回数从小到大排列。
- 本版无 SQL 修改。

### v8.8.12
- 修改课时管理顶部统计口径。
- 预定课时合计：所有预定课时的时长合计。
- 实际课时合计：
  - 实际课时按实际记录时长计算。
  - 待补课且计费的预定课时，也计入实际课时合计。
  - 取消课不计入。
- 预定课时费合计：
  - 按计费预定课时的“课程单价 × 预定时长”计算。
  - 不计费课时不计入。
- 实际课时费合计：
  - 计费实际课时按“课程单价 × 实际时长”计算。
  - 待补课且计费的预定课时按“课程单价 × 预定时长”计入。
  - 不计费补课、取消课不计入。
- 继续隐藏旧的“取消/放假数量”统计。
- 本版无 SQL 修改。

### v8.8.11
- 修复收入记录中“学费未选择学生”时，没有提示而直接回到系统主页的问题。
- 原因：
  - v8.8.10 只在 `saveForm` 外层做校验。
  - 部分保存按钮 / submit 路径没有进入该拦截分支。
- 本版改为三层校验：
  - 保存函数校验
  - 表单 submit 校验
  - 保存按钮 click 校验
- 收入分类为“学费 / tuition / 授業料”时，必须指定学生。
- 未指定学生时：
  - 不保存
  - 不关闭弹窗
  - 不跳转页面
  - 显示错误提示
  - 学生选择框高亮
- 本版无 SQL 修改。

### v8.8.10
- 完整课时导入支持新模板的“计费”列。
  - 是：计费
  - 否：不计费
- 课时状态增加“取消课”。
- 完整课时导入状态规则：
  - 已上课：有上课日期时生成实际课时，默认计费
  - 待补课：不生成实际课时，默认计费

  - 取消课：不生成实际课时，默认不计费
  - 如果模板填写了“计费”列，则以计费列为准
- 新增/编辑课时页面状态下拉同步增加“取消课”。
- 收入记录中，如果分类是“学费”，必须指定学生，否则报错。
- 修复月度结算下方“调整原因”无法删除到空白的问题。
  - 这不是刻意设置，而是预览刷新时回填导致。
- 本版无 SQL 修改。

### v8.8.9
- 修复学生月度结算没有计入跨月补课的问题。
- 月度结算同步课时管理状态规则：

### v8.8.8
- 修复完整课时导入后页面显示混乱的问题。
- 原因：Excel 的时间单元格被读取成 1899-12-30 的 Date 对象，页面直接显示了很长的 GMT 时间文本。
- 完整课时导入时将 Excel 时间统一转换为 HH:MM。
- 页面显示实际课时时间时，也统一清理异常的 1899/GMT 文本。
- 新增修复函数 `repairLessonTimeStringsV888()`：
  - 如果旧导入数据已经把异常时间字符串保存进数据库，可在 Console 手动执行一次。
- 本版无 SQL 修改。

### v8.7.5
- 再次修复结算锁定 RLS 报错。
- 原因：
  - v8.7.4 只给 authenticated 用户配置了结算锁定表权限。
  - 当前前端直连 Supabase 的运行角色可能是 anon。
  - 所以即使执行了 v8.7.4 SQL，insert 仍然会被 RLS 拦截。
- 新增 `school_v8_7_5_rls_anon_fix.sql`：
  - 允许 anon / authenticated 读取结算锁定记录
  - 允许 anon / authenticated 新增结算锁定记录
  - 允许 anon / authenticated 更新结算锁定记录
  - 允许 anon / authenticated 删除测试结算锁定记录
  - 同时补充 GRANT 权限
- 本版只修 RLS 权限，不改业务逻辑。
- 主界面版本号完整显示为 v8.7.5。
